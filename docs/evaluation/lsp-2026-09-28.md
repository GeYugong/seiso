# Language-server baseline: 2026-09-28

This record covers the first stdio language-server implementation and its
multi-buffer workspace loader. The [protocol reference](../reference/language-server.md)
owns behavior and limitations. This is implementation evidence for the editor
subproject, not completion of the other [M4 proposals](../design/roadmap.md#m4-ecosystem)
or evidence to promote a lint rule.

## Correctness checks

The local Windows run passed `cargo test --locked`: 266 tests passed and the two
existing tests requiring a downloaded corpus remained ignored. The change adds
29 tests across framing, text positions, workspace overlays, protocol replay,
and live subprocess sessions. The test sources are
[`tests/server.rs`](../../tests/server.rs),
[`tests/overlays.rs`](../../tests/overlays.rs), and
[`src/server/`](../../src/server/).

Cases include unsaved link targets, incoming anchor refresh, closed-buffer
restoration, nested policy, ignored paths, UTF-16 edits with CRLF, stale versions,
desynchronization recovery, capability negotiation, safe versioned edits,
configuration failures and recovery, non-Markdown target changes, and cache-event
filtering. Overlay analysis is compared with equivalent saved files. Quick fixes
are withheld on incomplete checks and rechecked after unannounced policy changes.

Formatting, strict Clippy, release build, repository Markdown checks, and all
146 Python tests passed. Python tests ran with UTF-8 mode from the resolved
worktree directory: the Windows directory alias otherwise causes existing
fingerprint tests to compare paths on different drives.

## Latency experiment

The release build used rustc 1.96.1 on Windows build 26200. Each run created a
fresh temporary workspace and processed 20 alternating heading edits with
`LNK001` and `LNK002`. The fixture verified incoming diagnostics on every edit
and confirmed that the source file on disk stayed unchanged.

| Documents | Parse cache | Startup (ms) | First refresh (ms) | Refresh p50 (ms) | Refresh p95 (ms) | Maximum (ms) |
| --- | --- | --- | --- | --- | --- | --- |
| 100 | Enabled | 367.362 | 168.276 | 49.168 | 53.816 | 56.601 |
| 100 | Disabled | 9.268 | 68.581 | 46.359 | 50.679 | 51.081 |
| 1000 | Enabled | 12.402 | 1552.435 | 554.776 | 621.834 | 627.259 |

Reproduce with the commands in the
[development guide](../guides/development.md#language-server-latency), adding
`--no-cache` or `--documents 1000` for the other rows. The executable launch is
included in startup, and publication of incoming diagnostic changes is included
in refresh timing.

These are single-machine observations, not a portable latency guarantee or a
comparison against another implementation. Startup varies substantially between
the first and subsequent launches. The small fixture does not demonstrate a
cache speedup. Full-workspace discovery and analysis remain visible at 1000
documents; expensive duplication rules and real editor rendering are not part
of this experiment. Incremental dependency tracking and cancellation need separate
design and evidence before claiming better large-workspace responsiveness.
